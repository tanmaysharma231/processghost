## Status legend

| Status | Meaning |
|---|---|
| built | built and exercised |
| partial | built, with known problems or unproven on real data |
| planned | designed, not built |

Kinds: **LLM** calls a model; **CODE** is plain Python; **LLM + CODE** calls a model and verifies or acts on its answer in code.

## Stage by stage

### In - Input and guards

A recording comes in. Anything unusable is refused before money is spent.

- Kind: CODE | Status: built | Model: none
- Takes in: A narrated screen recording (video with audio); Optional pre-meeting context files (planned, not built)
- Produces: Run directory with a copy of the video; manifest.json (code version, prompt hashes, settings, input hash)

**Decision tree**

1. Validate the file (core/guards.py)
   - IF Not a file, or empty -> Refuse with the reason (stops)
   - IF Larger than MAX_VIDEO_BYTES -> Refuse and name the limit (stops)
   - IF Duration unreadable (corrupt, or ffprobe missing) -> Refuse (stops)
   - IF Longer than MAX_VIDEO_DURATION_S -> Refuse: only short recordings are validated (stops)
   - IF Otherwise -> Accept and continue
2. Copy the video into runs/<run_id>/ and write manifest.json _Code version, hash of every prompt, models, thresholds, input hash._
3. Before every model call, check the cache (core/llm/cache.py)
   - IF Same provider, model, prompts, input, schema, images and temperature seen before -> Return the stored answer. Cost: $0.
   - IF Anything differs -> Call the provider and store the answer

**On failure:** A refused input stops the run before any file is copied or any call is made.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `MAX_VIDEO_BYTES` | `524288000` |
| `MAX_VIDEO_DURATION_S` | `900.0` |
| `MAX_RUN_COST_USD` | `2.0` |
| `KEEP_RUN_MEDIA` | `True` |
| `CACHE_ENABLED` | `False` |
| `LLM_TEMPERATURE` | `0.0` |
| `LLM_TIMEOUT_S` | `120.0` |

**Decisions that shaped it:** D3 Assume video only, no input events; D16 Client recordings use local or contracted models only; free hosted tiers for public or personal material; ADR-0009 Outside context enters as questions, never answers

**Measured**

- A second identical run cost $0.00 and produced the same sop.json (verified on the real clip).

**Known issues**

- Recordings may contain client data: see docs/data-handling.md. No redaction, no encryption at rest.

### 0 - Transcription

Audio to timed words. No reasoning, only timing and text.

- Kind: CODE | Status: built | Model: Whisper (OpenAI)
- Takes in: Audio extracted from the video (ffmpeg)
- Produces: Segments: id, start, end, text; Word-level timestamps attached to each segment

**Decision tree**

1. Extract audio, then transcribe with Whisper _Word and segment timestamps; words are attached to the segment that contains them._
2. Check the timing
   - IF One whole-transcript segment with no timing -> Mark timing_degraded: the document says its timestamps are unreliable, and the screen path is skipped (degrades)
   - IF Normal per-segment timing -> Continue

**On failure:** Fatal. There is no document yet, so a failed transcription ends the run (the cost is recorded).

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `MODEL_WHISPER` | `whisper-1` |

**Measured**

- Narration can lag or lead the action by 4 to 5 seconds (docs/24), which is why word times alone cannot align speech to screen.

### 1 - Writer

Turns the transcript into ordered steps, deliberately naive: a vague 'paste it here' stays vague.

- Kind: LLM | Status: built | Model: MODEL_TEXT (gpt-4o), one call
- Takes in: Every transcript segment at once (index, start, end, text)
- Produces: SOPDocument with steps (title, instruction, 'said' attributions) and appendix segments (small talk, with a reason)
- Prompt: `WRITER_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. One model call over the whole transcript _Whole context at once, so a step can span several segments._
2. Check the answer in code
   - IF A segment is missing, or counted twice -> Reject (stops)
   - IF A step has no 'said' attribution -> Reject: provenance is mandatory (stops)
   - IF Every segment accounted for exactly once, every step attributed -> Build the SOPDocument
3. Keep the speaker's own words _The prompt forbids substituting a more specific name than the speaker used, and a test asserts that specifics never narrated do not appear._

**On failure:** Fatal and the only fatal stage after transcription. No fallback: with no document there is nothing for later stages to work on.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `MODEL_TEXT` | `gpt-4o` |
| `LLM_TEMPERATURE` | `0.0` |

**Decisions that shaped it:** D10 Keep the Writer naive (v2); ADR-0001 The Writer is naive on purpose; ADR-0005 Every line is tagged as said or observed on screen; X2 One batched model call per stage over the whole context, not many small per-item calls; X3 Scenario facts live only in evals and tests, never in prompts or pipeline code

**Measured**

- Step count varied between runs on the same clip (5, 8, 9), which changes everything downstream.

### 2 - Reviewer

Finds where a newcomer would get stuck, by omission: a step pair with no verified connection becomes a gap.

- Kind: LLM + CODE | Status: partial | Model: MODEL_TEXT, one call, then plain Python
- Takes in: Draft steps; The full transcript
- Produces: Transitions (what carries between steps, with a verbatim quote); Flags: ambiguity or structural, each with a question, severity and window
- Prompt: `REVIEWER_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. Model: for each consecutive pair, name what carries across, with a quote copied from the transcript _Only when it honestly can. There is no ok/broken field to self-report._
2. Model: run four ambiguity checks on every step _Unresolved pointer words; missing names; unstated selection rules; unverified consequences ('it updates')._
3. Code: coverage check (merge_reviewer_output)
   - IF Transition has a quote that occurs in the transcript -> The pair is covered
   - IF Quote invented, paraphrased, empty, or the pair omitted -> Treated as silence: synthesize a structural flag (degrades)
   - IF The model already raised its own structural flag for that pair -> Keep the model's specific flag; skip the generic one
   - IF Transition between steps that are not consecutive -> Dropped

**On failure:** Non-fatal. On any failure the Writer's document ships unchanged with review_failed=True and zero flags, and sop.md shows a REVIEW FAILED banner.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `MODEL_TEXT` | `gpt-4o` |
| `LLM_TEMPERATURE` | `0.0` |

**Decisions that shaped it:** D11 Keep gap detection by omission and code-checked quotes (v2); ADR-0002 Find structural gaps by omission, grounded in verified quotes; ADR-0009 Outside context enters as questions, never answers; X2 One batched model call per stage over the whole context, not many small per-item calls; X3 Scenario facts live only in evals and tests, never in prompts or pipeline code; X13 Every step that moves or edits data must answer four questions: source, key, target, effect

**Measured**

- 10 runs on one fixed draft: grounded transitions 0 to 2 (zero in 4 of 10); structural flags 3 to 6; ambiguity flags 2 to 5; total flags only 7 to 9.
- Quote-grounding stopped invented quotes counting as coverage; it did not stop the model skipping the task.

**Known issues**

- Flag count is unstable between identical runs. What 'stable' should mean has not been decided (see Open questions).

### 0b - Screen timeline

Pixels only, no model: turns the video into discrete change events with before and after frames.

- Kind: CODE | Status: built | Model: none (local OpenCV; local RapidOCR for scene labels) | Runs only with `--screen`
- Takes in: The video
- Produces: screen_events.json: events, scenes, per-sample activity; Full-resolution before/after keyframes per event; A peak frame for an event that came and went (a dropdown opened and closed)

**Decision tree**

1. Sample frames at SCREEN_FPS, downscale, grayscale, blur
2. Difference against the previous sample, find changed boxes (diff_boxes)
   - IF Changed fraction below SCREEN_ACTIVE_FRAC -> Treat as noise (cursor, compression); not active
   - IF At or above it -> Active sample
3. Group active samples into events _A run ends after SCREEN_SETTLE_S of stillness; a burst after a still gap starts a new event._
4. Optional split (SCREEN_SPLIT_ON_LOCUS_SHIFT, off by default) _After a still sample, a change that does not touch the run's earlier changes starts a new event: two quick actions in different places._
   - IF Flag off (default) -> Changes inside the settle window stay one event
   - IF Flag on -> Split at the jump in where the screen is changing (degrades)
5. Keyframes: last still sample before the change, last active sample after it _Both stored at full resolution._
6. Classify the event from the net before/after difference
   - IF After frame is the before frame shifted vertically -> large_shift (a scroll); changes left after undoing the shift are kept as residual boxes, so an edit during a scroll is not hidden
   - IF Changed boxes span at least SCREEN_SCENE_COVERAGE of the frame AND at least SCREEN_SCENE_MIN_CHANGED of pixels changed -> scene_cut (a context switch); OCR the top and bottom strips as its label
   - IF Otherwise -> local (a cell, field or selection changed)
   - IF Before and after are identical but the screen changed in between -> transient: kept with its most-changed frame; an interaction, not a committed change

**On failure:** Non-fatal. On failure the run records screen_failed and continues as v2: no silent-step flags, no event evidence.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `SCREEN_FPS` | `3.0` |
| `SCREEN_ACTIVE_FRAC` | `0.0004` |
| `SCREEN_PIXEL_THRESH` | `25` |
| `SCREEN_MIN_BOX_AREA` | `150` |
| `SCREEN_SETTLE_S` | `1.0` |
| `SCREEN_SCENE_COVERAGE` | `0.3` |
| `SCREEN_SCENE_MIN_CHANGED` | `0.03` |
| `SCREEN_SCROLL_MIN_SHIFT_PX` | `8.0` |
| `SCREEN_SCROLL_MIN_RESPONSE` | `0.3` |
| `SCREEN_SPLIT_ON_LOCUS_SHIFT` | `False` |
| `SCREEN_LOCUS_MARGIN_PX` | `24` |

**Decisions that shaped it:** D1 Treat screen recordings as change points plus screenshots, not general video; D2 Build speech and screen timelines independently, then join on time; D4 Changed region is the primary locator; cursor is a hint; D5 Diff by thresholded pixels and connected components, at 2 to 5 fps; D6 One before/after keyframe pair per event (last static, first settled); D13 Screen stage and Align are non-fatal with fallback to v2 evidence; D15 Every stage works on a short rolling buffer; D17 Precompute the diff index for the whole video; call OCR and VLM only on demand; D19 Pass scene labels (OCR of tab or title per scene) as text for the surrounding window; ADR-0006 Build the screen timeline independently of the transcript; ADR-0010 Changed regions are merged by proximity, never dropped by size

**Measured**

- Found 7 events on the real 24 s clip, matching the draft labels (the labels were read off the same frames, so this proves little about recall).
- A spreadsheet sheet switch changed only about 10.8% of pixels, so a 'more than 40% changed' scene-cut rule never fires.

**Known issues**

- Thresholds were tuned on one clip. Two actions inside one second merge into one event unless the locus split is turned on (unmeasured). Transient, residual-box and split behaviour is tested on synthetic clips only. Web and ERP screens untested.

### 0c - Surface locators, event classes and anchors

Reads which application, sheet or page each frame shows from its chrome text, classifies every screen event by what changed (never by pixel size), and keeps selections as anchors tied to speech and later values by time. A cheap vision model reads only fields OCR could not.

- Kind: LLM + CODE | Status: partial | Model: none, except a cheap vision model (MODEL_VISION) for the few selected-cell fields OCR cannot read, one batched call | Runs only with `--screen`
- Takes in: Screen events and keyframes; OCR of each frame's top and bottom strips; Word-timed speech (for the cross-check only)
- Produces: Change records with a locator before and after, what kind of change it was, and its event class; contexts.json: each distinct context once, reused when the recording returns; A speech clue per context switch; anchors.json: selections tied to speech or later values; The list of screen activity that became no step, each with its reason
- Prompt: `READ_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. Per frame: pick the best-scoring profile (spreadsheet, web), else the generic fallback
   - IF A profile scores at least SURFACE_MIN_CONFIDENCE -> Extract its locator: application, document, sheet or page, selected cell, formula-bar content, and the strings it came from
   - IF None does -> Generic locator: the first title fragment only, low confidence (degrades)
2. Compare the before and after locators of each event
   - IF Different application, document, sheet or page -> app_switch, document_switch, sheet_switch or page_navigation
   - IF Same surface -> same_surface_edit
   - IF Either side is not recognised -> unknown: never a guess (degrades)
3. Build the context map _A new context when the locator changes (or an unrecognised scene cut); the existing one is reused when the same sheet or page returns. Observations only: no hypotheses are stored._
4. Repair unread selected-cell fields (spreadsheet only)
   - IF The cell reference validates -> Nothing to do
   - IF It does not -> Re-read with a CHANGED input (2x upscale, local contrast, taller strip); identical pixels would give the identical wrong answer
   - IF Still not valid -> Queue the top strip; one batched call to the cheap vision model transcribes all queued strips. Its answer must pass the same validator, is tagged read_by=vlm, and is capped per run (degrades)
   - IF Over the cap or the answer fails validation -> The field stays unread, never guessed (degrades)
5. Classify each event by state change, never by pixel size
   - IF The screen changed and came back -> transient: dropped, listed with its reason
   - IF A scroll with nothing left after undoing the shift -> view_only: dropped, listed with its reason
   - IF Application, document, sheet or page changed -> navigation
   - IF Text differs before vs after at the same place, or the formula bar changed on the SAME cell -> data_change
   - IF Only the selected cell moved -> selection: kept as an anchor
   - IF Anything else (unreadable, mixed) -> unclear: always kept (degrades)
6. Anchors: join selections to speech and later values by time
   - IF A pointer word or the cell's value is spoken near it AND a later data change puts the same value elsewhere -> Confirmed anchor with a role (source)
   - IF Only one of the two -> Candidate, shown as 'possibly <cell>', never as fact
   - IF Neither -> Listed as unused screen activity (degrades)
   - IF The value could belong to more than one change, or two anchors hold it -> The value signal is withheld: ambiguity yields candidates, never a guess (degrades)
7. Speech clue (corroboration, never a gate)
   - IF The speaker named the destination within the window (mostly after the event, because narration lags) -> found, with the lag
   - IF Nobody named it -> No clue: a possible silent navigation, not a verdict (degrades)
   - IF The event stayed on one surface -> Not computed

**On failure:** Non-fatal. On failure it records surface_failed and the run continues without locators; the Reconciler builds its own records as before.

| Setting | Value |
|---|---|
| `SCREEN_TEXT_CHANGE_MIN_RATIO` | `0.9` |
| `ANCHOR_VALUE_WINDOW_S` | `20.0` |
| `OCR_RETRY_VARIANTS` | `3` |
| `VLM_READ_MAX_CROPS` | `12` |
| `SURFACE_MIN_CONFIDENCE` | `0.4` |
| `SURFACE_SPEECH_WINDOW_BEFORE_S` | `2.0` |
| `SURFACE_SPEECH_WINDOW_AFTER_S` | `5.0` |
| `SURFACE_SPEECH_MIN_RATIO` | `0.6` |
| `CONTEXT_MAX_OCR_CHARS` | `800` |
| `SCREEN_RECORD_MAX_REGIONS` | `3` |
| `SCREEN_REGION_MAX_CROP_FRAC` | `0.5` |

**Decisions that shaped it:** ADR-0013 Surface locators are the context map; speech is corroboration, never a gate; X8 Speech is corroboration for a screen change, never a gate; X14 Screen events are classified by what changed in the application, never by how many pixels changed; X15 A selection is an anchor tied to speech and later values by time, confirmed only by two independent signals

**Measured**

- Real clip, no model calls: 3 contexts found, the second reused when the recording returned to it; every scored field (change kind, sheet position, sheet name, selected cell) matched the draft labels.
- The draft labels are not independent of the detector's own readings, so this is a regression check, not proof.
- OCR often garbles or drops the formula-bar glyph; the cell reference was recovered anyway, formula content only when legible. The third sheet showed no readable cell reference.

**Known issues**

- Event classes, anchors and the read fallback are unit-tested on synthetic records only; the class labels (expected_classes.json) are drafts a person has not confirmed.
- Pointer words are English only.
- The web profile has only synthetic tests; no web recording exists.
- A web-hosted spreadsheet scores as web when its URL and browser name outweigh the spreadsheet signals.
- A hosted vision model for unrecognised surfaces is deferred (it would send screen images to a provider).

### 2b - Align

Attaches screen events to flags. Also the fallback silent-step detector if the Reconciler fails.

- Kind: CODE | Status: partial | Model: none | Runs only with `--screen`
- Takes in: Steps and flags; Transcript timing; Screen events
- Produces: Each flag carries the ids of the events near it; Silent-step flags (only in fallback mode)

**Decision tree**

1. Attach events to every existing flag _An event counts if it falls inside the flag's window or up to SCREEN_ALIGN_LEAD_S before it: action leads speech, never trails it._
2. Silent-step detection (only when the Reconciler is off or failed)
   - IF Event inside a step's spoken span, or shortly before it -> Owned by that step
   - IF No step owns it -> Candidate silent step (degrades)
   - IF A step owns more than SCREEN_ALIGN_MAX_EVENTS_PER_STEP events -> The extras are candidates (degrades)
   - IF A flag already covers the same step pair -> No duplicate flag

**On failure:** Non-fatal: records align_failed and returns the document unchanged.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `SCREEN_ALIGN_LEAD_S` | `3.0` |
| `SCREEN_ALIGN_MAX_EVENTS_PER_STEP` | `2` |

**Decisions that shaped it:** D2 Build speech and screen timelines independently, then join on time; D9 Attach screen events to existing flags using a window of about plus or minus 3 s, with a longer lead before the flag; D12 Silent steps enter as structural flags, reusing Checker and inserted inferred steps; D13 Screen stage and Align are non-fatal with fallback to v2 evidence; X6 The Reconciler replaces Align's counting heuristic for silent steps; Align stays as the fallback

**Measured**

- On the real clip the Reviewer's flags already covered every event, so it raised no silent flag. Unproven on any data.

**Known issues**

- A fixed time window cannot align speech to screen: real segments are about 6 s long and narration lags the action. Superseded by the Reconciler for silent-step detection.

### 2c - Reconciler

For every step, says what changed on screen, quoting the OCR records. Anything it cannot quote is thrown away.

- Kind: LLM + CODE | Status: partial | Model: MODEL_TEXT, one call, then plain Python | Runs only with `--screen`
- Takes in: Steps with word-timed speech; One OCR change record per screen event (chrome before/after, changed regions before/after, and when available the surface locator, change kind and speech clue)
- Produces: Observed changes on each step ('Observed on screen: ... [observed @t]'); Flags: unspecified questions, said-but-not-shown steps, unsupported claims, silent events
- Prompt: `RECONCILER_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. Code: build change records by local OCR (cached by image content) _Top and bottom strips before and after, plus the largest changed regions before and after._
2. Model: one batched call over all steps and all records _Per step: events, what changed, evidence quotes, unspecified questions. Per event: its step or none. Per claim: supported or not._
3. Code: verify every quote
   - IF Quote (spaces and pipes removed) is in the record of an event the model declared for that step -> Keep the 'what changed' sentence
   - IF Not found, or taken from another event -> Drop the sentence; the step counts as said-but-not-shown (degrades)
4. Code: create flags (origin = reconcile)
   - IF Step has no grounded change -> Flag: narrated but nothing on screen matches; created already unresolvable (degrades)
   - IF Model listed an unspecified question -> Flag it (capped per step, duplicates dropped); already unresolvable: the evidence was read, so it goes to the recorder
   - IF A claimed consequence is not supported by a grounded quote -> Flag: blocking if the records show no change, caution if unclear (degrades)
   - IF An event no step explains -> Open silent-step flag; the Checker will describe it

**On failure:** Non-fatal. On any failure, or if no OCR engine is installed, it records reconcile_failed and falls back to Align's counting heuristic.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `RECONCILER_MAX_QUESTIONS_PER_STEP` | `3` |
| `SCREEN_RECORD_MAX_REGIONS` | `3` |
| `SCREEN_RECORD_MAX_CHARS` | `500` |
| `SCREEN_RECORD_CROP_PAD_PX` | `20` |

**Decisions that shaped it:** D12 Silent steps enter as structural flags, reusing Checker and inserted inferred steps; D14 Work file is the source of truth for hidden logic; video gives order and intent; ADR-0010 Changed regions are merged by proximity, never dropped by size; ADR-0013 Surface locators are the context map; speech is corroboration, never a gate; X1 Every step raises a 'what changed here?' question, answered from screen diffs; X2 One batched model call per stage over the whole context, not many small per-item calls; X3 Scenario facts live only in evals and tests, never in prompts or pipeline code; X4 Quote verification tolerates OCR noise: whitespace and pipes are removed before matching; X5 Reconciler flags are created already unresolvable and skip the Checker; X6 The Reconciler replaces Align's counting heuristic for silent steps; Align stays as the fallback; X10 Observations, inferences and open questions stay separate, and a flag records why it exists; X13 Every step that moves or edits data must answer four questions: source, key, target, effect; X15 A selection is an anchor tied to speech and later values by time, confirmed only by two independent signals

**Measured**

- First run: 2 of 6 required findings; every 'observed' line was a real fragment of a record, nothing invented.
- Described window chrome and missed the cell references that carry the useful detail (a prompt change to name locators is unmeasured: API credit ran out).
- Mapped 'paste' to the sheet-switch event, not the event where the value appeared.
- Marked 'the total updates' supported from the status bar's sum of the selected cell. Grounding checks a quote exists, not what it means.

**Known issues**

- False support for consequence claims has no fix yet.
- Record extraction is spreadsheet-shaped; web and ERP surfaces need their own profile.

### 3 - Checker

Resolves each open flag against the screen. Writes down what it saw before deciding, and 'unresolvable' is a valid answer.

- Kind: LLM | Status: partial | Model: MODEL_VISION (gpt-4o-mini) for images, MODEL_TEXT for text-only
- Takes in: Open flags, most severe first; Screen events attached to each flag
- Produces: A verdict per flag: resolved, contradicted or unresolvable; Inferred clauses on steps, or new inferred steps
- Prompt: `CHECKER_EVENT_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. Select flags
   - IF Status is open, sorted blocking first; first MAX_CHECKED_FLAGS -> Check them
   - IF Beyond MAX_CHECKED_FLAGS -> Marked unchecked, never dropped (degrades)
   - IF Estimated spend reaches MAX_RUN_COST_USD -> Stop starting new flags; the rest are marked unchecked (degrades)
2. Per flag: choose the evidence path
   - IF Flag has attached screen events -> Event path (below)
   - IF No events, or no screen timeline -> Marked unchecked: there is no evidence to check it against, so no model call is made (degrades)
3. Event path, level 0: nearest event, OCR text, text model _Evidence: full downscaled frame, numbered before/after tiles, OCR of chrome and regions._
4. Read the verdict
   - IF resolved or contradicted -> Apply it
   - IF resolved, but the observation shares CHECKER_ECHO_MAX or more of its words with the prompt -> Downgrade to unresolvable (it restated the prompt) (degrades)
   - IF unresolvable -> Level 1: the events around it (plus or minus SCREEN_ESCALATION_EVENTS) and, on OpenAI, the images; then stop. Maximum two calls per flag
5. Apply a resolution
   - IF Ambiguity flag resolved -> Append an inferred clause to its step; the narrated text is never rewritten
   - IF Structural flag resolved -> Insert a new inferred step between the two steps
   - IF contradicted -> Flag becomes blocking
   - IF unresolvable -> Terminal status; it goes back to the recorder as a question
   - IF The call fails -> That flag becomes check_failed; the run continues (degrades)

**On failure:** Non-fatal per flag. One failed call marks that flag check_failed and the run continues.

**Settings** (current values from `core/config.py`)

| Setting | Value |
|---|---|
| `MAX_CHECKED_FLAGS` | `20` |
| `SCREEN_EVIDENCE_FULL_WIDTH` | `1024` |

### 3c - Document rung (workbook)

Checks the workbook is the one in the recording, then answers what code can (which cell was used, what reads it, how rows are matched) and lets a short model loop try the rest, read-only. A formula states a rule; the screen only shows values. Every cited cell is checked.

- Kind: LLM + CODE | Status: partial | Model: MODEL_TEXT, a short loop of structured calls per flag; the profiler and the two lookup tools are plain code | Runs only with `--workbook`
- Takes in: Open and unresolvable flags, and blocking flags the video resolved (a cross-check); The workbook, as a copy; The cell trail: which cell was selected, on which sheet, when (read from the name box); Full-frame OCR of each sheet, for the match check
- Produces: workbook_profile.json: sheets, headers, columns (with uniqueness), formulas as written, layout quirks; cell_trail.json and workbook_match.json (match, partial, mismatch or unknown, with the reasons); Per flag: what the document rung did (answered, contradicted, candidates, no answer, skipped) with the cells it rests on; New flags for conflicts the data revealed, left for the person who recorded the process
- Prompt: `DATA_CHECKER_SYSTEM` (full text in `docs/21-pipeline-reference.md` and the explorer)

**Decision tree**

1. Check the workbook against the recording (no model)
   - IF Sheet count, or the content of a selected cell, disagrees -> mismatch: the workbook is NOT used, the report says so, every routed question is recorded as skipped (stops)
   - IF Only some words visible in the recording are not in the workbook -> partial: used, with a warning that answers are not verified against the recording (degrades)
   - IF Everything comparable agrees -> match
   - IF Nothing from the recording to compare -> unknown: stated in the report, never treated as a pass (degrades)
2. Withdraw wrong attributions in the video's claims _A number in a Checker claim that equals the value of a formula cell must be the value of a cell that depends, directly or through other formulas, on a cell this recording changed. Otherwise the claim is withdrawn (its inferred clause or step removed) and the question goes back to the person. Totals are computed from the cells because the file stores no results. It rejects wrong attributions; it cannot confirm a claim._
3. Answer from facts, no model
   - IF Effect: what else reads the cell that was changed -> The formulas that read it, with each literal criterion checked against the real cells; a criterion no cell satisfies becomes a new blocking question
   - IF Key: how the right row is picked -> Columns on the source sheet that carry the same text value as a cell in that row and are unique there; several candidates become a confirmation question, one is an answer
   - IF No trail cell to start from -> Left to the model loop; nothing is guessed (degrades)
4. Name the parameters and what would break next time (no model)
   - IF A value from the changed row sits in a repeating column and is typed into a formula as a literal -> A parameter (named from the column header), with a note that the formula must be changed for another period
   - IF A sheet name carries that value -> A note beside it, keeping the real sheet name: next period there will be another sheet, or this one is replaced
   - IF A repeating column with no such tie, or a sheet name that merely shares a word -> Not reported (degrades)
   - IF A step that is a result (something that happens by itself) -> Drawn as a result node off the action that causes it, with the formulas that produce it
5. Find 'one shown, many needed' (no model) _The range a formula reads that holds the changed cell, or the run of cells waiting for the same entry, says how many items the process covers; the recording changed one. Raised as a question for the person ("1 of the 8 cells in F18:F25 changed; is it repeated for the remaining 7?"), never added as a step. Needs a workbook._
6. Profile the workbook (no model) _Sheets, the header row (not assumed to be row 1), column kinds, samples and distinct values for low-cardinality columns, formulas collapsed per column plus one-off formula cells in full, merged ranges, empty columns, blank rows, header names shared across sheets. Facts only; it says whether the file has calculated values at all._
7. Route flags
   - IF Not answered by the video (open, unresolvable, unchecked, check failed) -> Send, rule and key questions first
   - IF Resolved by the video but blocking -> Send as a cross-check: the screen can show one value while the real rule differs
   - IF Over DOCUMENT cap (DATA_MAX_ROUTED_FLAGS) -> Recorded as skipped, never dropped (degrades)
   - IF No workbook supplied -> Stage does not run
8. Per flag: a loop of structured calls, each a lookup or a verdict
   - IF Lookup (read_rows or query_rows) -> Row-capped, cells truncated, formulas returned as written; a bad sheet, column or operator is an error the model can read and a wasted call
   - IF The same lookup again -> Refused and counted as wasted (degrades)
   - IF DATA_MAX_CALLS_PER_FLAG lookups used -> One more round that can only give a verdict
9. Check the verdict in code
   - IF answered or contradicted, citing cells a lookup returned -> Keep it; value and formula are copied from the lookup result, not from the model
   - IF A cited cell was never returned -> Dropped; with none left the verdict is downgraded to no answer (degrades)
   - IF candidates -> Kept as possible answers; the question to the person becomes a confirmation
10. Merge into the document
   - IF Answered -> The question is resolved (a slot is filled), citing the cells; the base text is never edited
   - IF Contradicted, even a question the video resolved -> Becomes contradicted and blocking; the person decides (degrades)
   - IF Candidates or no answer -> An open question becomes unresolvable: every automated source has been tried
   - IF The data revealed a new conflict -> A new flag (origin data) for the person; never answered by the same call

**On failure:** Non-fatal. A failed stage records document_failed; a failed question is skipped with the reason on the flag. The source workbook's hash is checked again at the end.

### All - Retries, cache and limits

### D1 - Treat screen recordings as change points plus screenshots, not general video

- Status: built
- Applies to: Screen timeline
- Why: Screens are static between discrete jumps, so "find when it changed, then read a few images" captures nearly all information
- Rejected: Native video VLM: most expensive, weakest at small screen text, and most "open video models" are generation models, not understanding models
- Source: docs/22

### D2 - Build speech and screen timelines independently, then join on time

- Status: built
- Applies to: Screen timeline, Align
- Why: Only an independent screen timeline catches steps that are never spoken
- Rejected: Transcript decides where to look (v2, or an agent calling `look(t)`): misses silent steps by design
- Source: docs/22

### D3 - Assume video only, no input events

- Status: built
- Applies to: Input and guards
- Why: Target source is a meeting bot; recordings will not come with click or keystroke logs
- Rejected: Recorder with event logging: simplest and most accurate, but not available in the target setting
- Source: docs/22

### D4 - Changed region is the primary locator; cursor is a hint

- Status: built
- Applies to: Screen timeline
- Why: Many steps are not clicks (typing, shortcuts, scroll), results often appear away from the cursor, and cursor detection is fragile across themes and compression
- Rejected: Crop around the mouse (original idea): misses dialogs, keyboard actions and remote effects
- Source: docs/22

### D5 - Diff by thresholded pixels and connected components, at 2 to 5 fps

- Status: built
- Applies to: Screen timeline
- Why: Catches a single cell changing; mean frame difference would miss it. Screens do not change faster than a few fps
- Rejected: Full 30 fps or mean-difference scoring: wasted compute, missed small changes
- Source: docs/22

### D6 - One before/after keyframe pair per event (last static, first settled)

- Status: built
- Applies to: Screen timeline
- Why: One pair captures the whole change regardless of event length; avoids sending 100+ frames
- Rejected: Fixed-interval frames per window (v2 Checker): redundant frames, change never isolated

### D7 - Send a full downscaled after-frame, stitched padded before/after crops of the changed regions, and OCR'd chrome text

- Status: built
- Applies to: Checker
- Why: VLM cost scales with pixels; crops cut cost, but only the full frame and the chrome (title, tabs, status bar) say which sheet, file or page you are on

### D8 - OCR first, vision only on escalation

- Status: partial

- Rejected: Diff only around Reviewer flags: misses silent steps and re-scans frames on every expansion. Model calls on every event: pays for steps already explained

- Status: partial

### D20 - Escalate deterministically: level 0 (nearest event), then once at plus or minus 2 events if `unresolvable`, then stop; no `needs_more_context` verdict

- Status: built
- Applies to: Checker
- Why: The model asking for more is self-report (D11): it over-asks or claims to be done. A fixed rule caps cost at 2 calls per flag and leaves `CheckerOutput` unchanged
- Rejected: Model-driven `needs_more_context` with a direction: smarter targeting but unreliable, a schema change and up to 3 calls per flag. Never expand: loses answers just outside the first window
- Source: docs/22

### ADR-0001 - The Writer is naive on purpose

- Status: built (Accepted, built)
- Applies to: Writer
- Why: The pipeline exists to find what the expert did not say. A Writer that tidies the transcript into a clean SOP also repairs the vague references ("paste it here"), and the gap disappears before anything can look for it. The Writer keeps the speaker's own words, including pointer words, and never substitutes a more specific name. A prompt rule says so, and an integration test asserts that specifics which are never narrated do not appear in the draft.
- Rejected: Let the Writer infer specifics from context: hides gaps and makes every later stage look better than it is.
- Source: docs/adr/0001-naive-writer.md

### ADR-0002 - Find structural gaps by omission, grounded in verified quotes

- Status: partial (Accepted, built; stability still open)
- Applies to: Reviewer
- Why: Asking a model "is this step connected to the next?" is biased toward yes. Self-reported confidence is the signal least worth trusting. The Reviewer is asked to name what carries between consecutive steps only when it honestly can, with a verbatim transcript quote. Plain Python checks the quote actually occurs in the transcript. Every consecutive pair without a verified transition becomes a structural flag. There is no ok/broken field to self-report.
- Rejected: Special-casing zero transitions: it would silently delete a true finding for a genuinely incoherent explanation. Asking the model to rate each step: self-report.
- Source: docs/adr/0002-gaps-by-omission-with-verified-quotes.md

### ADR-0003 - The Checker observes before it decides, and "unresolvable" is a valid answer

- Status: partial (Accepted, built; weak-answer problem open)
- Applies to: Checker
- Why: A confident wrong resolution is written into the SOP as if it had been seen. That is worse than an open question. The Checker must write what is literally legible in the evidence first, then decide using only that. It is told repeatedly that `unresolvable` is a real result (the answer lives in the recorder's head). A resolved answer to an ambiguity question must add a concrete detail not in the question. A resolved observation that mostly restates the prompt is downgraded to unresolvable.
- Rejected: A single verdict-plus-answer field: allowed vague but confident resolutions.
- Source: docs/adr/0003-observe-before-verdict.md

### ADR-0004 - Triage is a pure function with no model call

- Status: built (Accepted, built)
- Applies to: Triage
- Why: Whether an issue blocks a build, warns, or proceeds should be repeatable and auditable. `triage_flag(status, severity)` returns `proceed_with_assumption`, `proceed_with_flag` or `block_and_escalate`. Same document in, same output out. It produces `build_spec.json` and its escalation queue.
- Rejected: An LLM triage step: not repeatable, and nothing to audit.
- Source: docs/adr/0004-deterministic-triage.md

### ADR-0005 - Every line is tagged as said or observed on screen

- Status: built (Accepted, built)
- Applies to: Writer, Checker, Outputs
- Why: Two kinds of evidence (what the expert said, what the screen showed) mean different things to a reader. Mixing them hides which parts were assumed. Every step carries a `said` attribution with its transcript segments. Anything the Checker adds is a separate `inferred` clause with its frames, never merged into the narrated text. A raising Pydantic validator makes a document without complete provenance impossible to construct.
- Rejected: A soft completeness flag: easy to ignore and to spoof.
- Source: docs/adr/0005-said-vs-observed-provenance.md

### ADR-0006 - Build the screen timeline independently of the transcript

- Status: partial (Accepted; timeline built, silent-step value unproven)
- Applies to: Screen timeline
- Why: If the transcript decides where to look at the screen, a step that is performed but never mentioned is never examined. A plain-Python timeline turns the video into discrete change events (pixel difference, connected components, a settle rule, before/after keyframes at full resolution). The two tracks meet only at Align. The timeline needs no model call.
- Rejected: Native video understanding model: most expensive and weakest at small text. Transcript-driven lookup (v2): misses silent steps by construction.
- Source: docs/adr/0006-independent-screen-timeline.md

### ADR-0007 - The Checker's escalation is deterministic, never model-requested

- Status: built (Accepted, built)
- Applies to: Checker
- Why: Letting the model ask for more context is self-report again: models over-ask or claim to be done. It also changes the output schema and makes cost unbounded. Level 0 sends the nearest event as OCR text plus a text model. If the verdict is `unresolvable`, level 1 widens to the events around it and, on OpenAI, attaches images. A flag that is still unresolvable goes back to the recorder. Maximum two calls per flag.
- Rejected: A `needs_more_context` verdict with a direction: smarter targeting but unreliable and unbounded.
- Source: docs/adr/0007-deterministic-checker-escalation.md

### ADR-0008 - Idempotent runs through a content-addressed cache and one retry layer

- Status: built (Accepted, built)
- Applies to: Retries, cache and limits
- Why: The old policy retried every error three times on top of the SDK's own retries, including malformed answers, and its backoff was too short for the rate limits the Checker hit. A rerun repeated every paid call. Every model call is keyed by provider, model, prompts, input, schema, attached image bytes and temperature; a hit costs nothing. Retries are transient-only (rate limit, timeout, connection, 5xx) with jittered exponential backoff, a schema-mismatch is re-asked once, and the SDK's own retries are turned off. Every retry is written to the trace. Temperature is pinned to 0. Each run writes a manifest (code version, prompt hashes, models, thresholds, input hash).
- Rejected: Caching only at the pipeline level: any change anywhere re-pays everything.
- Source: docs/adr/0008-cache-and-single-retry-layer.md

### ADR-0009 - Outside context enters as questions, never answers

- Status: planned (Accepted design, not built (intake paused))
- Applies to: Reviewer, Input and guards
- Why: A model handed a hypothesis tends to confirm it, and a document-versus-reality contradiction is the most valuable finding. Open questions from a discovery tool or from source documents go only to the Reviewer. The Reviewer may close one only with a verbatim, code-verified transcript quote. A hypothesis counts as confirmed only if a Checker resolution reached without seeing it agrees.
- Rejected: Giving the Reviewer the facts to "verify": self-report with extra steps.
- Source: docs/adr/0009-questions-not-answers-for-outside-context.md

### ADR-0010 - Changed regions are merged by proximity, never dropped by size

- Status: partial (Accepted, built; unproven beyond synthetic tests)
- Applies to: Screen timeline, Reconciler, Checker
- Why: An event can have many changed boxes, and each consumer (the change record the Reconciler reads, the tiles the Checker sees) can show only a few. The first implementation kept the largest boxes by area. Pixel area says nothing about workflow importance: opening a dropdown changes a large area without changing business state, while one edited status cell or amount changes a few hundred pixels. Keeping the largest boxes drops exactly the small edit that matters when it sits beside a big change. When an event has more boxes than a consumer can show, the nearest boxes are merged into groups until the cap holds (`core/screen/regions.py`). Every original box ends up inside some group. A merged group that would cover most of the frame is split back when the cap still allows it. Scroll events keep only what remains after undoing the scroll (`residual_bboxes`), so an edit made during a scroll is not hidden under the "large_shift" label, and an interaction that came and went (a dropdown opened and closed) is kept as a transient event with its peak frame instead of vanishing.
- Rejected: Rank by changed area and keep the top few (the original behaviour, and a design-document-level rejection of importance-by-magnitude). A learned importance score: no labelled data exists to calibrate one, and it would need the semantic understanding it is meant to save.
- Source: docs/adr/0010-regions-merged-never-dropped-by-size.md

### ADR-0011 - Three independent triggers feed one investigation index, with coverage accounting

- Status: partial (Accepted, built; value unproven (one clip))
- Applies to: Investigations and coverage, Outputs
- Why: No single signal covers the recording. Transcript-driven lookup misses actions the speaker never mentions (ADR 0006). Pixel changes alone cannot say which changes matter. A screen-only view cannot tell that a spoken claim was never demonstrated. And when a flag cap or spend budget cuts the work short, the report used to print "Nothing is missing" regardless. Three independent triggers nominate stretches of the recording (`core/screen/investigate.py`): - **A, context transition:** a screen event that changed application, document, sheet or page, or a scene cut. - **B, transcript:** a flag raised from what was said, with the screen events attached to it. - **C, unexplained activity:** a screen event no narrated step accounts for, whether or not anyone was speaking about something else. Triggers that share an event are merged into one `Investigation` that keeps every reason. A transcript flag with no attached screen change is kept as its own investigation (the transcript asked and nothing on screen was located), not dropped. After the Checker runs, each investigation gets a status: examined, skipped for the flag cap, skipped for the spend budget, or unexamined. The SOP carries a `ScreenCoverage` summary and the report lists the spans not examined, replacing "Nothing is missing" with a caveat whenever coverage is incomplete.
- Rejected: A scalar priority score combining pixel change, transcript relevance and "unexplainedness": change magnitude is a poor proxy for importance, "unexplained" cannot be known before the region is understood (circular), and a number implies precision the variables do not have. Transcript-guided selection alone (ADR 0006). Fixed-rate frames sent to a vision model (kept only as a benchmark).
- Source: docs/adr/0011-three-triggers-one-investigation-index.md

### ADR-0012 - Evidence retrieval is a deterministic, budgeted library

- Status: partial (Accepted; library built and tested, not yet used by the Checker. A model-driven tool loop is an open experiment)
- Applies to: Investigations and coverage, Checker
- Why: The adaptive-evidence design calls for tools an agent can use to look at the recording: a full frame at a time, a crop, a before/after comparison, an episode summary, a wider interval. ADR 0007 already decided that the Checker's escalation is deterministic because a model that asks for more context tends to over-ask or claim to be done, and because that makes cost unbounded. The tools exist as plain functions (`core/screen/retrieve.py`) and nothing in them calls a model. Every artifact has a content-based id (video fingerprint, kind, time, box, padding, width), so asking for the same thing twice returns the same id with no decode and no charge, on this run or a later one. New artifacts are charged to an `InspectionBudget` (images, crops, expansions, re-inspections of one interval); when it is spent the call returns a recorded `Refusal`. Every call is reported with its latency and whether it was a cache hit. The Checker keeps its two-level deterministic escalation (ADR 0007); its evidence pack now carries the stable ids of what it showed, and they are written to the trace. Letting a model choose which tool to call is not built. It stays a documented experiment to run against the deterministic path once there is credit and more than one recording.
- Rejected: An agent loop as the default retrieval path (ADR 0007's reasoning, and no measurement shows it helps). Re-decoding the video on every request (cost and latency for no new information). Ids derived from file paths (they would differ between runs of the same recording).
- Source: docs/adr/0012-retrieval-as-a-deterministic-library.md

### ADR-0013 - Surface locators are the context map; speech is corroboration, never a gate

- Status: partial (Accepted; the spreadsheet profile matched the draft labels on one clip, the web profile is unproven)
- Applies to: Surface locators, event classes and anchors, Reconciler
- Why: Whether the application, sheet or page changed cannot be read from how many pixels moved: a spreadsheet sheet switch changed about 11% of pixels. Which sheet or page is showing is written in the frame's chrome (cell reference and formula bar, status bar, tab strip, URL, breadcrumb). Narration lagged the action by 4 to 5 seconds on the measured clip and some navigation was never narrated at all. A small profile per kind of surface reads the chrome text with no model and returns a `Locator` (application, document, location, title, focus, formula-bar content, the evidence strings it came from, a confidence). Profiles exist for spreadsheets and generic web pages, with a low-confidence generic fallback. Comparing the before and after locators of an event says whether it was an application, document, sheet or page change, or an edit on the same surface; when a profile is not confident the answer is "unknown", never a guess. A sheet is identified by its position ("Sheet 2 of 3") first because the name is easier for OCR to misread. The locators build a `ContextMap`: each distinct context is described once (its locator and capped OCR of the first full frame seen there) and reused when the recording returns to it. It stores observations only. A relationship such as "this column is the matching key" is a hypothesis and is not stored. Speech is a cross-check (`core/screen/speech_clue.py`): did the speaker name the place the event moved to, looking mostly forward in time because narration lags? A missing clue on a real switch is a signal (possible silent navigation), not a verdict, and a present clue never confirms the event on its own.
- Rejected: Using the changed-pixel fraction to decide a context change (it fails on sheet switches). Using speech as a gate for treating an event as navigation (it lags and is sometimes absent). A vision model on every context switch (cost and data handling, for a question usually answerable from text). Named profiles for specific ERP products before any recording of one exists.
- Source: docs/adr/0013-surface-locators-as-the-context-map.md

### ADR-0014 - One flow from what was said and what was shown, four questions per data step, and an evidence ladder

- Status: built (Accepted, built; unit-tested on synthetic data and the screen side dry-run on one real clip; the model-driven parts (slot questions, Reconciler actions and slot fills, the document loop) have not been run against a real model)
- Applies to: cross-cutting
- Why: The goal is a process flow with no missing steps. Four things stood in the way (checked in the code): 1. Screen findings never became steps. An unnarrated change became a flag asking what happened; observed changes were notes on spoken steps. The flow was the narration with annotations. 2. Gap finding depended on the Reviewer noticing vague wording. How rows were matched was never asked in four real runs, and no video or document can answer a question that is not raised. 3. Pixel change size says nothing about importance: a dropdown can change a third of the screen and mean nothing, a one-cell edit a fraction of a percent and be the process. 4. A question the video could not answer simply stayed open; the workbook the person worked in was never read, although rules (a formula, a column's contents) live there and the screen shows only values. - **Steps come from both sources.** An event nobody narrated that is a navigation or a data change, and whose action sentence is backed by a verbatim quote from that event's record, becomes a step marked "done on screen, not said" (`Attribution.kind = "shown"`), placed by time. Anything else stays a silent-change flag. - **Events are classified by what changed in the application** (`core/screen/classify.py`), never by pixel size: transient, view-only, navigation, data change, selection, unclear. Only positive proof drops an event; every dropped event is listed with its reason; unclear is always kept. When the selected cell moves, text that appears or vanishes because the cell's own content is shown or hidden is a selection, not an edit. - **A selection is an anchor** (`core/screen/anchors.py`), tied to speech (a pointer word or the cell's value spoken near it) and to a later data change that puts the same value elsewhere. Two independent signals confirm it; one makes it a candidate worded "possibly"; ambiguity yields candidates, never a guess. A confirmed anchor answers a copied value's source and target with no model. - **Every step that moves or edits data must answer four questions** (`core/slots.py`): source, key, target, effect. A missing answer becomes a question by omission, like a missing transition. A slot counts as said only with a verbatim transcript quote. - **Every question climbs a ladder: video, then document, then the person who recorded the process.** The video rung is the Reconciler, the anchors and the Checker. The document rung (`core/data/`) is a deterministic profiler, two read-only lookup tools and a short bounded loop of structured calls; every citation must match a cell a lookup actually returned, and the value and formula are copied from the lookup result, not from the model. The person is last for answering and final for intent: a conflict between sources (the formula says one thing, the stored values another) is never settled by the pipeline; it reaches the person as a conflict, and a question the data only narrowed to candidates reaches them as a confirmation. - **The workbook is checked against the recording first** (`core/data/match.py`): the sheet count, the content of selected cells and the visible words. A mismatch stops the workbook being used and the report says so; a partial match is used with a warning. The first real run showed why: the supplied file had one total row where the recording had two. - **Answers that code can compute are computed** (`core/data/answer.py`, `facts.py`): which cell was selected (the cell trail, read from the name box), which formulas read it with their literal criteria checked against the real cells, and which columns carry the same value on two sheets. The model loop only takes what is left. - **A number in a video claim must belong to a cell that depends on what the recording changed** (`core/data/guard.py`). The Checker read the billed total and attached it to the actualized total one row below; grounding the number in the evidence could not catch that. Totals are computed from the cells because the file stores no results. - **"One shown, many needed" is found from the workbook** (`core/data/repeat.py`): the range a formula reads that holds the changed cell (or, with no formula, the run of cells waiting for the same entry) says how many items the process covers; the recording changed one. It is raised as a question, not added as a step. - **A result is drawn as a result, and reuse is made visible** (`core/data/params.py`, `report/flow.py`): a step that is a consequence ("the total updates automatically") is a "result" node hung off the action that causes it, labelled shown or claimed-not-shown from the screen and with the formulas that produce it from the workbook. The workbook decides which values are probably parameters (a value from the changed row that sits in a repeating column AND is typed into a formula), keeps the real names, and adds notes: a formula with this run's value typed into it, and a sheet whose name carries it ("potential future issues if this is run for another period"). Each parameter becomes a question for the person. A sheet name alone is not enough, because it is often a coincidence of vocabulary. - **The flow is drawn with its gaps** (`report/flow.py`): step nodes marked said / shown / both, dashed gap nodes where a piece is missing, each linked to its question. A flow with no gap nodes says "no known gaps", never "complete". - **Reading failures are retried with a changed input, then read once by a cheap vision model on the failed crop only** (`core/screen/read_fallback.py`), behind the same validator as OCR; over the per-run cap a field stays unread.
- Rejected: A generic "needs data" tag on flags (it would be set on nearly everything); a pixel or area threshold for importance; dropping selections or turning each into a step; letting the data pass overwrite the video's answer; native model tool calling for the lookup loop (it would bypass the shared retry, cache and cost layer; the structured loop is bounded and replayable instead); freeze-and-replay machinery for the comparison (A, B and C are read off one run's per-question rung record).
- Source: docs/adr/0014-flow-from-said-and-shown-with-an-evidence-ladder.md

## Open questions

Decisions not yet made, or problems without a fix.

### Q1 - What should 'stable' mean for the Reviewer's flag counts?

- Applies to: Reviewer
- Why it matters: Ten runs on one fixed draft gave 7 to 9 total flags but the structural/ambiguity split moved and grounded transitions ranged 0 to 2. The evals cannot score stability until the target is defined.
- Options: A stable total; The same flagged locations each run; The same bucket for each issue

### Q2 - How do we stop a consequence claim being marked supported by a change that is not the one claimed?

- Applies to: Reconciler, Reviewer
- Why it matters: The Reconciler accepted the status bar's sum of the selected cell as proof that a sheet total updated. Quote checking confirms a quote exists, not what it means.
- Options: Require the supporting quote to come from a region other than where the action happened; Treat any claim about a total as open unless a record shows the value it would produce; Ask the recorder instead of the model

### Q3 - How do we stop the Checker resolving structural flags into confident false steps?

- Applies to: Checker
- Why it matters: A real run inserted 'the pasted value updates the total in the Transactions-March sheet', which no event shows. It is the largest remaining source of false statements.
- Options: Require an observation naming a changed value, not a description of the screen; Do not insert steps from a single event; Stricter specificity rule for 'resolved'

### Q4 - Should events split when two actions fall inside one second?

- Applies to: Screen timeline, Reconciler
- Why it matters: Switching sheet and selecting a cell merged into one event, so 'copy' was mapped to nothing.
- Options: Split on a changed-region jump (built behind SCREEN_SPLIT_ON_LOCUS_SHIFT, off by default, unmeasured); Shorten the settle window; Leave merged and let the Reconciler read both

### Q5 - How are web and ERP surfaces handled?

- Applies to: Screen timeline, Surface locators, event classes and anchors, Reconciler, Checker
- Why it matters: A generic web profile (URL, title, breadcrumb) now exists but has only synthetic tests. No web recording exists, and a web page change is not a large pixel change.
- Options: Record a web walkthrough as a second eval case first; Detect chrome regions from what never changes between events; A hosted vision reading for unrecognised surfaces (sends screen images to a provider)

### Q6 - Who confirms the event labels?

- Applies to: Screen timeline
- Why it matters: The draft labels were read off the detector's own keyframes, so a perfect score proves nothing about recall. A person has to watch the video.
- Options: The recorder; A reviewer on the engagement

### Q7 - When does intake (outside context as questions, never answers) resume?

- Applies to: Reviewer, Input and guards
- Why it matters: It is the integration point for a discovery tool. Source ingestion is built; the intake prompt is not. Paused until the screen path is trusted.
- Options: After the findings score is acceptable; In parallel

### Q8 - Will the workbook or other work file be available with the recording?

- Applies to: Reconciler
- Why it matters: Why row 18 was chosen, and what the total formula depends on, are not on screen. Only the file recovers them (D14).
- Options: Usually; Sometimes; Never

### Q9 - How is client data protected at rest?

- Applies to: Input and guards, Retries, cache and limits
- Why it matters: Runs and the cache are unencrypted; nothing is redacted before it is sent to the provider.
- Options: Encrypted volume and scheduled cleanup (documented); Redaction before sending; Local models only

### Q10 - What combination of differences keeps tiny cell changes without flooding the index with cursor and scroll activity?

- Applies to: Screen timeline
- Why it matters: Thresholds were tuned on one clip. Region merging means a small edit is no longer dropped from a record, but whether it is detected at all still depends on SCREEN_ACTIVE_FRAC and the box floor.

### Q11 - When does a context need another full frame?
