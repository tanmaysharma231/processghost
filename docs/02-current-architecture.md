# 02 - Current Architecture (as-is)

This document describes the system that exists today in
`process-ghost-incredible-node-qh4q-main/`. No opinions, no proposed fixes -- those live in
`06-known-gaps.md` and Part 3. Every claim below cites `file:line`.

## 1. What the folder is

A Next.js 14 application generated by "Lyzr Architect" (see the badge script embedded in
`app/layout.tsx:32` and the `architect.new` branding). The generator produces a full template
(50+ shadcn/ui components, RAG library, scheduler library, iframe error-reporting harness) and the
app-specific code is layered on top. Most of the template is never used by ProcessGhost.

There is no `.git` in this folder, no `node_modules`, and no `.env.local` -- only `.env.example`.
The app cannot run as checked out; it needs `npm install` and a real `LYZR_API_KEY`.

## 3. Runtime topology

```
Browser (app/page.tsx, React state machine)
   |
   |  POST /api/agent  { message, agent_id, assets? }        -- submit
   |  POST /api/agent  { task_id }                            -- poll (client-side loop)
   |  POST /api/upload { FormData(files) }
   v
Next.js API routes (app/api/agent/route.ts, app/api/upload/route.ts)
   |
   |  x-api-key: LYZR_API_KEY
   v
Lyzr hosted platform: https://agent-prod.studio.lyzr.ai
   - POST /v3/inference/chat/task        (submit)
   - GET  /v3/inference/chat/task/{id}   (poll)
   - POST /v3/assets/upload              (file upload)
```

The critical fact: **orchestration lives in the browser**. `app/page.tsx` decides which agent to
call next, builds each prompt from the previous agent's output, and drives the judge loop. Lyzr
only executes single agent calls; it has no knowledge of the six-agent pipeline as a unit. The
`workflow.json` graph is a design artifact, not something any runtime reads and executes.

## 4. Request lifecycle for one agent call

Traced end to end via `callAIAgent` (`lib/aiAgent.ts:84-179`):

1. Client POSTs `{ message, agent_id, user_id?, session_id?, assets? }` to `/api/agent`
   (`lib/aiAgent.ts:91-101`) through `fetchWrapper` (`lib/fetchWrapper.ts`), which also forwards
   any error to the parent iframe if running inside the Architect editor.
2. `submitTask` (`app/api/agent/route.ts:178-246`) validates `LYZR_API_KEY` is set
   (`route.ts:144-153`), fills `user_id`/`session_id` if absent (`route.ts:192-193`), and POSTs to
   `LYZR_TASK_URL = {LYZR_AGENT_BASE_URL}/v3/inference/chat/task` (`route.ts:7-9, 206-213`).
   Returns `{ task_id, agent_id, user_id, session_id }` (`route.ts:240-245`).
3. Client receives `task_id` (`lib/aiAgent.ts:114-124`) and enters a polling loop
   (`lib/aiAgent.ts:126-156`): delay `= min(300 * 1.5^attempt, 3000)` ms, hard ceiling
   `POLL_TIMEOUT_MS = 5 * 60 * 1000` (`lib/aiAgent.ts:78, 130-131`). Each iteration POSTs
   `{ task_id }` back to `/api/agent`.
4. `pollTask` (`app/api/agent/route.ts:251-327`) proxies `GET {LYZR_TASK_URL}/{task_id}`. If Lyzr
   reports `status: 'processing'`, returns `{ status: 'processing' }` and the client loops again
   (`route.ts:278-279`; client side `lib/aiAgent.ts:145-147`). If `status: 'failed'`, returns a
   normalized error envelope (`route.ts:283-293`). If completed, the raw `task.response` is
   JSON-stringified, unwrapped through an `{ response, module_outputs }` envelope check if present
   (`route.ts:296-308`), parsed via `parseLLMJson` (`route.ts:310`), and shaped via
   `normalizeResponse` (`route.ts:317`) before being returned as
   `{ success: true, status: 'completed', response: {status, result, message, metadata},
   module_outputs, timestamp, raw_response }` (`route.ts:319-326`).
5. `callAIAgent` returns that envelope, spread with `agent_id/user_id/session_id`
   (`lib/aiAgent.ts:150-155`), to whichever call site in `page.tsx` invoked it.

Timeout after 5 minutes returns a synthetic failure response client-side (`lib/aiAgent.ts:158-167`);
Lyzr itself is not told to cancel the task.

## 5. File upload lifecycle

`uploadFiles` (`lib/aiAgent.ts:184-227`) builds a `FormData` and POSTs to `/api/upload`. The route
(`app/api/upload/route.ts`) requires `LYZR_API_KEY` (`route.ts:11-26`), re-wraps each `File` as an
`ArrayBuffer`-backed `Blob` before forwarding (`route.ts:49-57`, comment: "ensure proper
serialization"), and POSTs to `{LYZR_AGENT_BASE_URL}/v3/assets/upload` (`route.ts:6, 59-65`). On
success it returns `{ success, asset_ids, files, total_files, successful_uploads, failed_uploads,
message, timestamp }` (`route.ts:81-90`). `asset_ids` is the only field the orchestrator consumes
(`app/page.tsx:516-520`) and it is passed to the Transcription agent alone -- see
`03-agent-pipeline.md` section "video reaches only agent 1".

`export const maxDuration = 120` is set on both `app/api/agent/route.ts:5` and
`app/api/upload/route.ts:4`, and `next.config.js` sets `experimental.serverActions.bodySizeLimit =
'100mb'` (`next.config.js:24-27`) to accommodate video uploads.

## 6. Configuration surface

From `.env.example` and code references:

| Variable | Read at | Purpose |
|---|---|---|
| `LYZR_API_KEY` | `app/api/agent/route.ts:9`, `app/api/upload/route.ts:7` | Required. `x-api-key` header on every Lyzr call. Routes 500 without it. |
| `LYZR_AGENT_BASE_URL` | `app/api/agent/route.ts:7`, `app/api/upload/route.ts:6` | Overrides `https://agent-prod.studio.lyzr.ai`. |
| `LYZR_USER_ID` / `NEXT_LYZR_USER_ID` | `app/api/agent/route.ts:192` | Fallback `user_id` if the client didn't supply one. |
| `NEXT_PUBLIC_LYZR_AGENT_BASE_URL` | `lib/agent-fetch-interceptor.ts:9` | Template-only, used by the unused interceptor. |
| `IS_PAID_USER` | `app/layout.tsx:23` | Gates whether the Architect badge script renders. |

No database, no auth, no multi-tenant user model. `user_id`/`session_id` are randomly generated
UUID-based strings per call unless supplied (`app/api/agent/route.ts:34-40, 192-193`).

## 7. Build and deploy

- `package.json` scripts: `dev` (`next dev --turbo -p 3333`), `build`, `start` (`-p 3333`), `lint`.
- `next.config.js:11-18` disables both TypeScript build errors (`ignoreBuildErrors: true`) and
  ESLint during build (`ignoreDuringBuilds: true`) -- see gap register entry 10.
- `netlify.toml` -- Netlify Next.js plugin deploy target.
- `Dockerfile` -- two-stage build, standalone Next.js output, non-root `nextjs` user, exposes port
  `3333`.

## 8. Dependencies of note (`package.json`)

`lyzr-architect` (`^latest`) -- an npm package providing database/auth helpers (`initDB`,
`createModel`, `authMiddleware`, etc., documented at length in `CLAUDE.md:429-583`). ProcessGhost
has no database and never imports this package; it is generator scaffolding present because the
template always includes it. `react-icons` is used throughout `app/sections/*.tsx` despite
`CLAUDE.md:13` mandating `lucide-react` only -- see gap register entry 11.
